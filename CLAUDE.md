# hello-world-desktop — Project Map

## Framework / Runtime
Tauri v2 (Rust backend) + Vite + vanilla TypeScript frontend (no framework). Node 22 for tooling, Rust stable for the native shell.

## Key Directories
- `src/`            — frontend (TypeScript, HTML, CSS) — Vite-built, runs inside the Tauri webview
- `src-tauri/`       — Rust backend (Tauri commands, window/app config, native capabilities)
- `src-tauri/icons/` — app icons for bundling, generated by `tauri icon`

## Entry Points
- `index.html` — frontend HTML entry (Vite root)
- `src/main.ts` — frontend TypeScript entry
- `src-tauri/src/main.rs` — native binary entry, calls into `src-tauri/src/lib.rs`
- `src-tauri/tauri.conf.json` — app identifier, window config, bundler targets

## Conventions
- Frontend ↔ backend calls go through Tauri's `invoke()` (see `@tauri-apps/api`) — define new native commands in `src-tauri/src/lib.rs` with `#[tauri::command]` and register them in the `invoke_handler`.
- `npm run tauri dev` for a live dev build with hot reload; `npm run tauri build` for a release bundle. Both require a display — cannot run headless (e.g. inside this container without a GUI/X server). `cargo check` in `src-tauri/` is the way to verify the Rust side compiles without a display.
- Package identifier: `com.thesuitestthing.helloworlddesktop`.

## Test Framework
None configured yet.

## Available Agents
- Frontend Agent (suffix: `frontend`) — the only agent role active in this project. It owns both the TypeScript frontend and the Rust backend, since this is a single-container desktop app with no separate backend service.
